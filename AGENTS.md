# Bongoponji contributor instructions

Preserve Bengali-first UI and date-specific provenance. Keep civil calendar, astronomy and observance rules separate. Publish religious data only through the verified record gate. Record independent references, comparisons and redistribution clearance before approving output. Run npm test, npm run check and npm run build for each releasable milestone. Update PROGRESS.md and KNOWN_LIMITATIONS.md.

The scheduled calendar workflow runs each month for the current year and each October for the next year. It uses standard public-repository runners and requires no paid service or API keys. For a failed run, inspect its report and correct the underlying reference or rule before rerunning. Only add reviewed source rows that can be stored in the public repository. Keep exact date-specific tolerances and the explicit conflict holds.

When an applicable edition appears in the [PAC English index](https://packolkata.imd.gov.in/rashtriya-panchang-english.php), only add dates that have reviewed, reusable comparison inputs. Dispatch with `YYYY` or `YYYY-MM` and read the report. A missing `REFERENCE_REVIEWED` row cannot approve a candidate. Keep the 9 December 2026, 31 January 2027 and 5 August 2027 conflict holds.
